- **Статус:** описан / автоматизируется / автоматизирован

Заполнять в порядке **P → O → C → I → S → E**, как на разборе. Секции ниже идут
по буквам, чтобы читалось как SIPOC, но начинать нужно с шагов.

## S — Suppliers (поставщики)
Кто или что запускает процесс, откуда приходит вход.

## I — Inputs (входы)
Что именно приходит: заявка, файл, сообщение, звонок. Формат и объём.

## P — Process (шаги)
Колонку «Модель / код / человек» заполняем на субботе 2.

| № | Шаг | Кто делает | Время | Модель / код / человек |
|---|---|---|---|---|
| 1 |  |  |  |  |
| 2 |  |  |  |  |
| 3 |  |  |  |  |

## O — Outputs (выходы)
Что получается на выходе и в каком виде.

## C — Customers (потребители)
Кто получает результат и что для него значит «хорошо».

## E — Expectation (ожидание в цифрах)
Поле, которого нет в классическом SIPOC. Без него процесс описан, но непонятно,
зачем его трогать. Две цифры, обе настоящие:

- **Сейчас:** <!-- сколько тратим и что за это получаем: часы, люди, деньги, штук в месяц -->
- **Хотим:** <!-- та же единица измерения, другая цифра -->

Если процесса ещё нет и его делал бы наёмный человек — считай его часы:
«ассистент тратил бы N часов в неделю». Это тоже цифра «сейчас».

## Узкое место
Где реально теряется время. Один пункт, а не список.

## Что автоматизируем первым
Один шаг. Самый дорогой по времени, самый повторяющийся.

## Примеры
Папка с именем этого файла, внутри `examples/` — для `process/01-x.md` это `process/01-x/examples/`:
- `inputs/` — 5–10 входов как есть: письма, заявки, вакансии, что угодно
- `outputs/` — 3–5 выходов, которые сделал сам и которыми доволен

Без чужих персональных данных и без ключей. Это материал для субботы 2:
на нём пишется первый системный промпт. Сам промпт живёт в папке агента,
в штабе — решение, почему он такой.
