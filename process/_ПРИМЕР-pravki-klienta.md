# Процесс: правки от клиента по проекту (Капибара)

- **Владелец процесса:** Андрей
- **Дата разбора:** 19.09.2026 (суббота 1)
- **Статус:** описан

Границы: начало — клиент прислал правку в Telegram; конец — правка задеплоена,
клиент получил сообщение «готово». Пилотный проект — Капибара, потом
масштабируем на остальные.

**Не входит в процесс:** крупные нелинейные правки, которые по сути мини-проект
(оценка → КП → проект). Порог «правка / мини-проект» в часах ещё не зафиксирован —
см. открытые вопросы.

## S — Suppliers (поставщики)
- Клиент (контактное лицо) — правки, согласование стоимости. Канал: Telegram
- Андрей — классификация, вычитка плана, верификация
- ТЗ проекта — Google Docs, критерий для спорных случаев «баг / дополнение»
- Репозиторий проекта — GitHub (код, CLAUDE.md, контекст)
- Claude Code — план, реализация, деплой
- Хостинг / прод — доступы, среда для проверки

## I — Inputs (входы)
- Правка: текст в Telegram, иногда голосовые и скриншоты. ~15 штук в неделю
- Знание проекта (в голове) + ТЗ для спорных случаев
- Ставка $150/час — для оценки платных дополнений
- Доступ к репозиторию, CLAUDE.md проекта
- Доступы к проду / хостингу, деплой-скрипт или CI

## P — Process (шаги)
Колонку «Модель / код / человек» заполняем на субботе 2.

| № | Шаг | Кто делает | Время | Модель / код / человек |
|---|---|---|---|---|
| 1 | Получить правку из Telegram | Андрей | — |  |
| 2 | Разобрать на пункты, классифицировать: баг (бесплатно) / дополнение (платно) | Андрей | — |  |
| 3 | *(только дополнение)* Оценить по ставке и согласовать стоимость с клиентом | Андрей + клиент | — |  |
| 4 | Описать задачу в Claude Code в план-моде | Андрей | — |  |
| 5 | Вычитать план, ответить на вопросы | Андрей | — |  |
| 6 | Реализовать и задеплоить | Claude Code | — |  |
| 7 | Верифицировать результат на проде | Андрей | — |  |
| 8 | Написать клиенту «готово» | Андрей | — |  |

Время по шагам не разложено: по словам владельца, время уходит не в конкретный
шаг, а в переключения — каждый шаг это «открыть, дождаться, посмотреть».
Всего ~24 минуты на правку.

Развилка «баг / дополнение» — один процесс, не два. Отличие — один
дополнительный шаг (3). Если платная ветка обрастёт переговорами и счетами —
выделим отдельно.

## O — Outputs (выходы)
- Задеплоенная правка на проде
- Сообщение клиенту «готово»
- По платным: счёт / запись «сколько должен» для учёта

## C — Customers (потребители)
- Клиент — правка на проде + сообщение. «Хорошо» = сделано, работает, сказали когда
- Андрей как владелец — учёт денег по платным дополнениям

## E — Expectation (ожидание в цифрах)
- **Сейчас:** ~15 правок в неделю, ~6 часов времени Андрея в неделю (~24 ч/мес), ~24 мин на правку. Один проект
- **Хотим:** ~1 час в неделю: правки копятся, раз в неделю вычитка плана и верификация пачкой

Экономия: ~20 ч/мес × $150/ч ≈ **$3 000/мес** на одном проекте, дальше
масштабируется на остальные проекты.

## Сейчас / хотим / стало
| Метрика | Сейчас | Хотим | Стало |
|---|---|---|---|
| Время на один прогон | ~24 мин | ~4 мин (1 ч / 15 правок) |  |
| Количество в неделю | ~15 | ~15 |  |
| Людей задействовано | 1 (Андрей на всех шагах) | 1 (только вычитка + верификация) |  |
| Стоимость прогона | ~$60 (24 мин × $150/ч) | ~$10 |  |

## Узкое место
Андрей — ручной диспетчер между шагами. На каждую из 15 правок в неделю —
8 переключений контекста: открыть Telegram, открыть Claude Code, описать,
подождать, прочитать, подождать, проверить, написать. Время теряется не в шагах,
а в том, что процесс запускается по одной правке и требует человека на каждом
стыке. Второе, поменьше: критерий «баг / дополнение» живёт в голове — агент
его не повторит, пока он не выписан.

## Что автоматизируем первым
Шаги 1–4 одним куском: **сбор правок из Telegram → разбор на пункты и
классификация → сборка недельного батча → запуск план-мода → план приходит
в Telegram на согласование.** Это самое повторяющееся (15 раз в неделю) и
именно тут человек нужен меньше всего. Вычитка плана (5) и верификация (7)
остаются за Андреем.

Целевая картина (со слов владельца): пятница вечером, все правки недели
собраны в один батч, агент на VPS прогнал план-мод, прислал план в Telegram.
Андрей отвечает на вопросы или одобряет. Claude Code реализует, гоняет
eval / верификационные тесты, присылает уведомление. Андрей проверяет,
отмечает «завершено», клиенту уходит сообщение.

## Открытые вопросы
- **Батч раз в неделю vs баги сразу.** Клиент с багом ждёт до пятницы — устроит ли?
  Вариант: баги — сразу, дополнения — батчем. Нужно решить и согласовать с клиентом.
- **Порог «правка / мини-проект»** в часах — не зафиксирован.
- **Деплой без ручной верификации.** Claude Code деплоит на прод до того, как
  Андрей посмотрел (шаг 6 → 7). Нужен staging или деплой после одобрения?
- **Критерий «баг / дополнение»** — выписать явно, с примерами из реальных правок.
